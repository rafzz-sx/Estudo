  2. SUPABASE — AUTENTICAÇÃO (o que precisa ser conferido no painel)
================================================================================

  IMPORTANTE ENTENDER: esta plataforma NÃO usa o Supabase Auth. O login é
  próprio, com JWT assinado pela API do Next.js. Então boa parte das
  configurações de Auth do painel não se aplica aqui.

  O que AINDA assim vale conferir:

  2.1  Confirme que o Supabase Auth está mesmo sem uso
       Dashboard → Authentication → Users
       Se a lista estiver vazia, está tudo certo: ninguém entra por ali.

  2.2  Desative provedores de login que você não usa
       Dashboard → Authentication → Providers
       Deixe tudo desligado. Provedor ligado e esquecido é porta aberta.

  2.3  URLs de redirecionamento
       Dashboard → Authentication → URL Configuration
       Só é relevante se um dia migrar para o Supabase Auth. Por ora,
       mantenha a lista vazia ou só com o seu domínio.

  2.4  MFA para a SUA conta do Supabase
       Isso sim é crítico e não tem a ver com os alunos: proteja a conta
       que administra o banco.
       Dashboard → clique no seu avatar → "Account Settings" → "Security"
       → ative "Two-Factor Authentication"

  2.5  Proteção contra senha vazada
       Não se aplica: a validação de senha é feita pelo código da
       plataforma (mínimo 8 caracteres, maiúscula, número e especial —
       está em /api/auth/recuperar e /api/auth/register).

  As variáveis que o código usa hoje:

  ┌─────────────────────────────────┬────────────┬──────────────────────────┐
  │ Variável                        │ Obrigatória│ Onde é usada             │
  ├─────────────────────────────────┼────────────┼──────────────────────────┤
  │ NEXT_PUBLIC_SUPABASE_URL        │ SIM        │ lib/supabase.ts          │
  │ NEXT_PUBLIC_SUPABASE_ANON_KEY   │ SIM        │ lib/supabase.ts          │
  │ SUPABASE_SERVICE_ROLE_KEY       │ SIM 🔒     │ lib/supabase.ts (server) │
  │ JWT_SECRET                      │ SIM 🔒     │ lib/auth.ts              │
  │ JWT_ACCESS_EXPIRATION           │ não (36000)│ lib/auth.ts              │
  │ JWT_REFRESH_EXPIRATION          │ não (36000)│ lib/auth.ts              │
  │ NEXT_PUBLIC_APP_URL             │ SIM        │ redirecionamentos        │
  │ RESEND_API_KEY                  │ não 🔒     │ envio de e-mail          │
  │ EMAIL_FROM                      │ não        │ remetente                │
  │ UPSTASH_REDIS_REST_URL          │ não 🔒     │ (ainda não usada)        │
  │ UPSTASH_REDIS_REST_TOKEN        │ não 🔒     │ (ainda não usada)        │
  └─────────────────────────────────┴────────────┴──────────────────────────┘

  🔒 = segredo. NUNCA ponha o prefixo NEXT_PUBLIC_ nessas.

  REGRA DE OURO: tudo que começa com NEXT_PUBLIC_ é embutido no JavaScript
  que vai para o navegador. Qualquer visitante lê no DevTools. Se uma chave
  secreta ganhar esse prefixo, ela vaza para todo mundo na hora.

  COMO SEPARAR POR AMBIENTE
  1. Em cada variável, clique no lápis para editar
  2. Marque as caixas: Production / Preview / Development
  3. Recomendação: use um projeto Supabase SEPARADO para Preview e
     Development. Assim um teste em branch nunca apaga dado real de aluno.
     Hoje os três ambientes apontam para o mesmo banco.

  4. SUPABASE — BACKUP E RECUPERAÇÃO
================================================================================

  A DIFERENÇA ENTRE OS DOIS (importa muito)

  Backup automático diário
    Uma fotografia do banco, uma vez por dia. Se der problema, você volta
    para a foto mais recente.
    Se o backup foi às 3h e o problema foi às 22h, você perde 19 horas de
    estudo, XP e conversa dos alunos.

  Point-in-Time Recovery (PITR)
    Grava tudo continuamente. Você volta para QUALQUER minuto dos últimos
    7 dias — inclusive "um minuto antes do DELETE errado".
    É pago (add-on do plano Pro).

  O QUE VERIFICAR
  1. Abra https://supabase.com/dashboard → seu projeto
  2. Menu lateral → "Database" → "Backups"
  3. Veja o que aparece:

     Plano Free      → SEM backup automático. Você está por sua conta.
     Plano Pro       → backup diário, guardado por 7 dias
     Pro + add-on    → PITR disponível para ativar

  SE VOCÊ ESTIVER NO PLANO FREE
  Faça um backup manual você mesmo, com alguma regularidade:
     1. Dashboard → Database → Backups → "Download backup"
     ou, se tiver a CLI instalada:
     supabase db dump -f backup-$(date +%F).sql

  RECOMENDAÇÃO
  Considerando que a plataforma guarda progresso de estudo de menores de
  idade, sem backup você não tem como reparar um acidente. É o item de
  maior custo-benefício depois do vazamento da chave.
